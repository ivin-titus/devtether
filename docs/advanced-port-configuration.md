# Advanced Port Configuration

DevTether is designed to work out of the box with zero configuration by automatically configuring unprivileged ports for its internal DNS and optionally configuring your OS to allow privileged binding for the reverse proxy.

If you need to manually change DevTether's default ports in your `devtether.yaml` after running `devtether init`, here is exactly how the system reacts and what you need to do.

---

## 1. Customizing the Proxy Port

By default, DevTether's reverse proxy can bind to **Port 80**. 
If you choose to change the proxy port in `devtether.yaml`:

### Unprivileged Ports (`1024` and above)
If you change `proxy.port` to an unprivileged port like `8000`, `8080`, or `3000`:
- **Action Required:** None.
- **Why?** The Linux kernel restricts ports below `1024`. Any port `1024` or above can be claimed by a standard user without `setcap` capabilities or `sudo`. It will just work.

### Privileged Ports (below `1024`)
If you change `proxy.port` to `443` or keep it at `80`:
- **Action Required:** You must run the daemon with `sudo devtether up` (macOS/Linux) OR manually apply `setcap` (Linux only).
- **Why?** To bind to privileged ports without running as root, the DevTether binary needs explicit OS-level privileges. On macOS, this strictly requires running with `sudo`. On Linux, you can bypass `sudo` by granting explicit kernel capabilities. `devtether init` can apply this for you on Linux, but if you reinstall the binary or move it, you can apply it manually:
  ```bash
  # Linux Only:
  sudo setcap cap_net_bind_service=+ep $(which devtether)
  ```

---

## 2. Customizing the DNS Port

By default, DevTether's internal DNS daemon binds to **Port 5335**.
If you edit `devtether.yaml` and change `dns.bind` (e.g., to `127.0.0.1:5300`), the DevTether daemon will flawlessly boot up on `5300`. 

However, **your system's `.localhost` domains will stop resolving.**

### Why does this happen?
When you ran `devtether init`, the wizard explicitly hardcoded your OS resolver (e.g., `systemd-resolved` or macOS resolver) to forward `.localhost` traffic to DevTether's unprivileged `5335` default. This ensures deterministic, fail-fast behavior. If you change the daemon's port, the OS resolver is left blindly forwarding traffic to a port where DevTether is no longer listening.

### How to fix it
If you want to customize the DNS port, **you must manually update the OS resolver configuration to match.**

**On Linux (systemd-resolved):**
1. Open the configuration file generated by the wizard:
   ```bash
   sudo nano /etc/systemd/resolved.conf.d/devtether.conf
   ```
2. Change `DNS=127.0.0.1:5335` to match your new custom port (e.g., `DNS=127.0.0.1:5300`).
3. Restart the resolver:
   ```bash
   sudo systemctl restart systemd-resolved
   ```

**On Linux (dnsmasq - e.g., some Arch Linux setups):**
1. Open the configuration file:
   ```bash
   sudo nano /etc/dnsmasq.d/devtether.conf
   ```
2. Change the port at the end of the server line (e.g., change `server=/localhost/127.0.0.1#5335` to `#5300`).
3. Restart dnsmasq:
   ```bash
   sudo systemctl restart dnsmasq
   ```

**On Linux (Custom Setups / NetworkManager / Vanilla `/etc/resolv.conf`):**
If `devtether init` skipped the automatic setup because it didn't find `systemd-resolved` or `dnsmasq`, you have two options:
1. **Option A (Recommended):** Install and enable `dnsmasq` or `systemd-resolved`, which act as smart local DNS routers capable of forwarding specific TLDs (`.localhost`) to custom ports (`5335`).
2. **Option B (Port 53 Bind):** Standard `/etc/resolv.conf` **does not support custom ports**. It strictly queries port `53`. If you want to rely purely on `/etc/resolv.conf`, you must configure DevTether's `dns.bind` to `"127.0.0.1:53"` in `devtether.yaml`. Note that binding to port 53 is a privileged operation, so you will need to run the daemon with `sudo devtether up`. Then, ensure `nameserver 127.0.0.1` is in your `/etc/resolv.conf`.

**On macOS:**
1. Open the resolver file:
   ```bash
   sudo nano /etc/resolver/localhost
   ```
2. Change `port 5335` to your new custom port.
3. The change should take effect immediately (or you may need to clear the DNS cache via `sudo dscacheutil -flushcache`).

> **Note:** We do not automate this edge case in `devtether init` to optimize for the 99% path where users stick to `5335`. Power users altering DNS bindings are expected to align their OS resolver manually.
